DataStore Migration Guide

Move ALL your players' saved data from your old game to your new game — safely, in the right order.

1

Before you startWhat you need

  • Two Roblox experiences — your old game (has the data) and your new game (needs the data).
  • Python 3 installed on your PC (free, from python.org).
  • An Open Cloud API key for both games (step 3 shows how).
  • About 20 minutes and a cup of coffee.
If your new game never had players yet, this whole process is still worth doing — it copies everything over so your players find their game waiting for them.
2

Find your games' IDsUniverse ID & Place ID

Every Roblox game has two numbers: a Universe ID (the whole game) and a Place ID (the level). You need both, for both games.

  • Go to create.roblox.com → Creations
  • Open your old game → click … → Copy Universe ID (note it down)
  • The Place ID is the number in the game's URL: roblox.com/games/123456789/MyGame → 123456789
  • Do the same for your new game
Write all four numbers down now: OLD universe, OLD place, NEW universe, NEW place. You'll paste them into the config in step 6.
3

Check your codeFind your DataStore names

Open your old game in Roblox Studio and look for where it saves data — search your scripts for:

DataStoreService:GetDataStore("YourStoreName")

Every "YourStoreName" string is a DataStore name you must copy. Typical examples:

"ProfileStore V1", "TimeStats", "PlayerData_v1_".."79229339887184"
Note: some store names end with the old place ID (like PlayerData_v1_79229339887184). That is normal — the toolkit rewrites the suffix to your new place ID for you.
4

Secret keyCreate your Open Cloud API key

  • Open create.roblox.com → Credentials
  • Click Create API Key
  • In Access, add both experiences (old game AND new game)
  • Enable the DataStore permissions (read and write)
  • Copy the key → paste it into a new text file, e.g. C:\Users\You\Downloads\roblox key data.txt (one line, nothing else)
Never share your API key. Never put it in chat, never paste it in the repo, never upload it. It is the password to your game's data. The toolkit reads it from the file — that's the safe way.
5

SetupInstall Python

  • Go to python.org/downloads and download Python 3
  • Run the installer — tick "Add Python to PATH" before installing
  • Verify by opening a terminal and typing:
python --version
If you see something like Python 3.12.x, you're ready.
6

Get the toolkitDownload the repo

  • Open github.com/CBE-STUDIO/roblox-datastore-migration
  • Click Code → Download ZIP
  • Extract the folder somewhere easy, e.g. C:\Users\You\roblox-datastore-migration
cd C:\Users\You\roblox-datastore-migration
7

ConfigurationFill in config.py

Copy the example config and open it:

copy scripts\config.example.py scripts\config.py

Then edit scripts/config.py and fill in:

  • API_KEY_FILE → the path to your key file (step 4)
  • OLD_UNIVERSE / OLD_PLACE → your old game's numbers (step 2)
  • NEW_UNIVERSE / NEW_PLACE → your new game's numbers (step 2)
  • STORES → the list of DataStore names you found (step 3)
config.py is private. The repo already ignores it with .gitignore — never commit it.
8

Run 1Back up the old game

This reads every key out of your old game and saves it to your PC. The old game is never changed — read-only.

python scripts\old_backup.py

It creates files in old_backup\ (one per DataStore). When it finishes, your whole old data is safely on your PC.

Done? Keep these backup files. They are your parachute — even if the internet dies, your data is safe.
9

Run 2Retry anything that failed

Sometimes a request fails (internet hiccup, rate limit). Retry fixes them automatically:

python scripts\retry_errors.py

Run it until it says everything is clean before moving on.

10

Run 3Build the migration plan

Now the toolkit plans the move — it rewrites store name suffixes for your new place ID and applies safe merge rules:

python scripts\build_ops.py
  • Numbers (coins, minutes) → keep the maximum of old and new
  • Tables → merged field by field
  • Lists → union (no duplicates)
  • Never deletes anything already in the new game

The plan lands in mig\ops.json. Anything uncertain is noted in mig\conflicts.txt for you to review.

11

Run 4Migrate!

The moment of truth — this writes all the data into your new game (10 threads, resumable):

python scripts\migrate_oc.py

Every write is logged to mig\applied_keys.jsonl. If it crashes, just run it again — it continues where it stopped instead of restarting.

Running the command twice is safe — it skips keys that already made it over.
12

Last checkVerify in your new game

  • Open your new game in Roblox Studio — run it and check a few players
  • Their coins, items and progress should be there
  • Follow the full checklist in docs/08-VERIFY.md
  • Leaderboards need one extra step — see docs/07-LEADERBOARDS.md
All good? You're done — your players just found their save intact.
✓

Why this is safeThe golden rules

Old game read-onlywe only GET from your old game — nothing is changed or deleted there.
Backup firsteverything is saved to your PC before anything is written.
Merge, never wipeexisting new-game data is kept; numbers never go backwards.
Logged & resumablecrash? run the same command again — it continues, not restarts.
Your key stays secretread from a file, never committed, blocked by .gitignore.
Rate-limit friendlyevery request retries with back-off on 429 / 5xx.
